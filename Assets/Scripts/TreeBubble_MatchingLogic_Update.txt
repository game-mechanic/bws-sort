1. ADJUSTABLE SWING STRENGTH:
------------------------------

New Inspector Setting:
  Swing Strength: [Slider 0-5] (default 2.0)

Location:
  TreeBubbleManager → Chain Settings → Swing Strength

Effect:
  • 0.0 = No swing (static hanging)
  • 1.0 = Gentle sway
  • 2.0 = Medium swing (default, natural)
  • 3.0 = Strong swing
  • 5.0 = Wild swing (very active)

Real-time Adjustment:
  • Change value in Inspector
  • [Clear Bubbles]
  • [Spawn Bubbles In Editor]
  • Enter Play mode to see effect

Recommended Values:
  • Mobile: 1.5-2.0 (gentle, battery-friendly)
  • Desktop: 2.0-3.0 (more dramatic)
  • Calm aesthetic: 1.0-1.5
  • Energetic feel: 2.5-4.0

2. NO SWINGING IN SLOTS:
-------------------------

Old Behavior:
  • Bubble moves to slot
  • Physics still active
  • Bubble continues swinging in slot
  • Looks glitchy and unnatural

New Behavior:
  • Bubble moves to slot
  • DisablePhysics() called
  • Rigidbody2D set to Kinematic
  • Velocity zeroed out
  • SpringJoint2D destroyed
  • Chain line hidden
  • Bubble completely static in slot

Implementation:
  In MoveToSlot():
    bubble.DisablePhysics();
  
  In TreeBubble.DisablePhysics():
    • rb.bodyType = Kinematic
    • rb.linearVelocity = Vector2.zero
    • rb.angularVelocity = 0f
    • Destroy spring joint
    • Hide chain line

Result:
  ✓ Clean, professional look
  ✓ Bubbles "lock in" to slots
  ✓ No distracting movement
  ✓ Clear visual state change

3. NEW MATCHING LOGIC:
----------------------

OLD LOGIC (Adjacent):
  • Check last 4 bubbles in slots
  • All 4 must be adjacent
  • All 4 must match

  Example:
  Slots: [R] [R] [R] [R] [B]
         └─────Match!─────┘
  
  Slots: [R] [B] [R] [R] [R]
         └─No Match (not last 4)

NEW LOGIC (Any 4):
  • Count all bubbles by category
  • If ANY category has 4+ bubbles
  • Pop first 4 of that category

  Example:
  Slots: [R] [B] [R] [G] [R] [R]
         ↓      ↓      ↓   ↓
         └──────Match! (4 Reds)────┘
  
  Slots: [R] [R] [B] [R] [R]
         ↓   ↓      ↓   ↓
         └────Match! (4 Reds)──┘

Benefits:
  ✓ More forgiving gameplay
  ✓ Easier to make matches
  ✓ Less frustrating
  ✓ Strategic depth (can skip colors)
  ✓ More combinations possible

ALGORITHM DETAILS:
------------------

CheckForMatches() now:

1. Dictionary to count categories
   Dictionary<BubbleType, List<int>>

2. Loop through all slotted bubbles
   For each bubble:
     - Get its category
     - Add index to category's list

3. Check each category
   For each category:
     - If count >= 4
     - Pop first 4 indices
     - Return (one match at a time)

4. No match found
   Log current slot summary

Code:
```csharp
Dictionary<BubbleType, List<int>> categoryIndices = ...;

foreach (var kvp in categoryIndices)
{
    if (kvp.Value.Count >= 4)
    {
        List<int> indicesToPop = kvp.Value.GetRange(0, 4);
        PopBubbles(indicesToPop);
        return;
    }
}
```

═══════════════════════════════════════════════════════════════════

POPPING LOGIC:
--------------

PopBubbles(List<int> indices):

1. Sort indices (for consistent popping order)
2. Reverse (pop from end to avoid index shift)
3. Remove from slottedBubbles list
4. Animate each with scale-up
5. Stagger by 0.1s for cascade
6. Particles at peak
7. Destroy GameObjects
8. Shift remaining bubbles to fill gaps

Example:
Indices: [0, 2, 4, 5]
Sorted: [0, 2, 4, 5]
Reversed: [5, 4, 2, 0]

Remove 5 → [R][B][R][G][R][_]
Remove 4 → [R][B][R][G][_][_]
Remove 2 → [R][B][_][G][_][_]
Remove 0 → [_][B][_][G][_][_]

After shift:
[B][G][_][_][_][_]
